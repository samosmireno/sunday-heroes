# Drizzle over Prisma

The data access layer is Drizzle on the core query builder and SQL, with migrations generated by `drizzle-kit generate`, committed and reviewed as SQL, and applied by a release command. The relational query API is not used, and `drizzle-kit push` never runs outside a scratch database.

## Why

The domain's invariants are partial and functional unique indexes: one open Season per Competition, nickname and name uniqueness on a normalised value, one unvoided ballot per voter per match. Prisma cannot declare them; the current repository carries the one that exists as custom SQL its engine cannot see. Drizzle declares them in the schema and generates them into reviewable migrations. The derived reads want SQL over a scope, and the row locks the acts need exist only on the core builder.

## Consequences

Drizzle 0.45 is the stable line and 1.0 is in release candidates; staying on the core builder keeps the upgrade to a migrations-folder move rather than a rewrite of every read. The partial index predicates are written with the `sql` tag rather than the operator helpers, which emit a parameter into the DDL.
